Historia de Usuario N°5

**Como** administrador o usuario propietario
**quiero** actualizar los datos de un usuario
**para** corregir mi perfil o el de otros

**Tarjeta:** Actualización **parcial** de un usuario (`PATCH`). Solo se actualizan los campos que
lleguen (`exclude_unset=True`), se normaliza el email si viene, se valida unicidad y, si viene
`password`, se rehasha. Protección por ownership (ADMIN o el propio usuario).

**Criterios de Aceptación (Gherkin):**
- Dado un ADMIN o el propietario
  Cuando actualiza algunos campos de un usuario existente
  Entonces recibe 200 con el usuario actualizado (solo cambian esos campos)
- Dado un cambio de email a uno que ya usa OTRO usuario
  Entonces recibe 409
- Dado un usuario que conserva su propio email
  Entonces no se considera duplicado (200)
- Dado un cambio de contraseña
  Entonces el hash se regenera (la contraseña nunca se guarda en texto plano)
- Dado un usuario inexistente
  Entonces recibe 404
- Dado un email inválido o una contraseña corta
  Entonces recibe 422

**Specification by Example:** update parcial, email normalizado, cambio de password rehashada,
email en uso por otro (409), mismo email OK, usuario inexistente (404), sin campos no rompe.
