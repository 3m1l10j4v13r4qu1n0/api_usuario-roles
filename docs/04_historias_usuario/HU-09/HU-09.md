Historia de Usuario N°9

**Como** administrador
**quiero** asignar un rol a un usuario
**para** otorgarle permisos específicos (ej. elevarlo a ADMIN)

**Tarjeta:** Asignación de rol a un usuario. Requiere rol `ADMIN`. Si el rol o el usuario no
existen → 404. Al asignar, se **invalida el cache de estado** (USR-RN12): el nuevo rol se refleja
en la autorización **sin re-login** (verificado por integración).

**Criterios de Aceptación (Gherkin):**
- Dado un ADMIN autenticado, un rol existente y un usuario existente
  Cuando asigna el rol al usuario
  Entonces recibe 200 con el usuario que incluye el nuevo rol en `ids_roles`
- Dado un usuario con un token ya emitido
  Cuando un ADMIN le asigna el rol ADMIN
  Entonces el próximo request del usuario ya tiene el nuevo rol (sin re-login)
- Dado un rol inexistente
  Entonces recibe 404 "El rol ... no existe"
- Dado un usuario inexistente
  Entonces recibe 404 "El usuario ... no existe"
- Dado un usuario SIN rol ADMIN
  Entonces recibe 403

**Specification by Example:** asignación exitosa, revocación/asignación en caliente sin re-login,
rol inexistente (404), usuario inexistente (404), sin ADMIN (403).

**Acceptance TDD:** cubiertos por `test_uc9_asignar_rol.py` (fakes) +
`test_asignar_rol_se_refleja_sin_relogin` (integración).
