Historia de Usuario N°6

**Como** administrador
**quiero** dar de baja a un usuario
**para** que deje de poder autenticarse

**Tarjeta:** Baja **lógica** (`activo = False`, nunca se borra físicamente). Requiere rol `ADMIN`.
Al dar de baja se **invalida el estado en cache** (USR-RN12), por lo que un token vigente deja
de funcionar en el próximo request (revocación en caliente).

**Criterios de Aceptación (Gherkin):**
- Dado un ADMIN autenticado y un usuario existente
  Cuando da de baja al usuario
  Entonces recibe 200 y el usuario queda con `activo = False`
- Dado un usuario dado de baja
  Cuando intenta autenticarse
  Entonces recibe 401 (credenciales inválidas)
- Dado un usuario inactivo con un token aún vigente
  Cuando consulta un endpoint protegido
  Entonces recibe 401 (token inválido)
- Dado un usuario inexistente
  Entonces recibe 404
- Dado un usuario SIN rol ADMIN
  Entonces recibe 403

**Specification by Example:** baja lógica, login rechazado post-baja, inactivo con token vigente → 401,
404 inexistente, 403 sin ADMIN.
